## Harness: finhub-harness (primary capability — the harness factory)

**Goal:** A Claude plugin (`.claude-plugin/plugin.json`, skills in `skills/`) that builds agent teams and their skills for any domain, on Claude Code, Claude chat or Claude Cowork. Ported from revfactory/harness v2.1.0 (Apache-2.0) and extended with surface adaptation, an adversarially audited Authority List, mutation-tested QA and licence-tiered enrichment from the pinned reference harnesses.

**Trigger:** "build / design / extend / audit / migrate a harness", "create an agent team", "borrow pattern X from repo Y" → use the `finhub-harness` skill. "Harness retrospective", "evolve the harness", "fold this feedback in" → use the `finhub-harness-evolve` skill. Package for Cowork or chat with `scripts/package-plugin.sh`.

## Harness: master-finhub (secondary capability — the runtime build team)

**Goal:** A six-agent team (mining, ranking, design, adversarial audit, build, QA) that mines the fourteen pinned `references/` submodules, ranks what is worth adopting, designs runtime slices or one adoption at a time with an audited Authority List, and builds and verifies it into the Python runtime in `src/master_finhub/` or the plugin under `skills/` and `.claude/`. Slices 1-11 are built; slice 12 (factory) is superseded by the `finhub-harness` skill above.

**Rigor:** the judge and QA are `gated`, assigned by the owner (Daniel, 2026-10-14, confirming the approved plan Part A; the unit kind is class `other` and gated is his assignment, not a default), but only in the full lane, which runs when he says full for an item. The table row for the unit kind is `light` since 2026-10-28, on his words 'Quick unless I say full (Recommended)' after he said the team was too heavy and too slow for small tasks, so the default lane is Quick: the lead builds and runs the repo's own gates, with no architect, judge or QA agent. No agent selects, raises or lowers the level, and none classifies a unit. A unit runs light only through a `rigor:<scope>/<item>` row in `WAIVERS.md` from his own quoted words, and the table is lowered only through a `rigor:<scope>/table` row. The table is the `## Rigor` section of `.claude/skills/master-finhub-orchestrator/SKILL.md`; the rules are `skills/finhub-harness/references/quality-gates.md` 3-10 (adapted from references/openrig/docs/reference/sdlc-conventions.md:20-24 (Apache-2.0)).

**Trigger:** Any request to build, re-run, update or improve the Master FinHub runtime (including partial re-runs such as "re-run only the judge" or "rebuild slice N"), and any request to improve finhub-harness from the reference repos ("pick the best capabilities", "capability backlog", "adopt X from Y", "build C3") → use the `master-finhub-orchestrator` skill. Building a harness for another domain is the `finhub-harness` skill above, not this one.

**Code navigation:** for "who calls X", "what breaks if I change X" or "where is X defined" in `src/`, `tests/`, `scripts/` or `skills/`, run `scripts/codegraph.sh callers|callees|impact|query X` (CodeGraph, local, about 1 s warm) before Grep. Grep stays the tool for `references/`, prose and strings; the index excludes `references/` by design.
