## Attack results on what rev 2 introduced

Blocking: ATK4 only (above).

Follow-ups (non-blocking; each reproduced unless marked by inspection):

1. SIGHUP overrides `nohup`. `_signals_raise` installs the SIGHUP (and SIGTERM) handler unconditionally, so a runner started with SIGHUP ignored (`nohup python -m master_finhub.evals.gates g.json &`, or `trap '' HUP`) dies on SIGHUP: reproduced, `kill -HUP` after 1.5 s of a 4 s gate gave rc 129 and no report (rev 1 ignored the signal and finished). SIGINT ignored is honoured (rc 0, pass), which is the sensible convention. The suite passes under nohup only because the runner overrides the inheritance. Suggested fix: skip a signal whose current disposition is `SIG_IGN` (and let the test child reset SIGHUP/SIGTERM in its boot line like SIGINT), or document the override in Decision 9.
2. Programs on the wrapper list that run a shell WITHOUT naming one, in the same class as `su` and `watch` that rev 2 refuses outright, are accepted and ran: `flock lk -c "echo A; echo B > out.txt && echo $0"` -> pass, stdout `A\n/bin/bash\n`, out.txt created; `script -qec "echo C > out2.txt; echo D >> out2.txt" /dev/null` -> pass, both writes done. By the same rule `runuser -c`, `parallel 'a;b' ::: x` (GNU parallel runs `$SHELL -c`) and `sudo -s`/`-i` are accepted at plan time (plan results). `env -S 'sh -c id'` (one string argument holding the shell name) is also accepted (a wrapper given a shell; the rule compares whole arguments). All are covered in words by "any program that itself starts a shell ... NOT detected", so this is not a falsified claim, but `runuser` is `su` by another name and `flock`/`script`/`parallel` sit on the list as if covered. Move runuser (and the `-c` forms of flock/script, parallel) to SHELL_RUNNERS or name them under Does not cover; name `env -S`.
